# Demo 中文界面参考方案

> 用途：比赛 Demo 轻量 UI 改造参考。以下方案只改变信息呈现，不改变 Raw / 证据可靠性 / 调整后评价 公式、HUMAN Gate、参数或正式数据。

## 共同视觉基线

- 米白背景、深墨绿色文字、青绿色主色、橙色低支持、红色无有效证据。
- 顶部固定显示 DEVELOPMENT ONLY · HUMAN GATE NOT RUN，避免把 AI_PROVISIONAL 结果误读为正式验证。
- 所有方案都把三件事放在首屏：原始表现、证据支持度、最终状态。
- NO_EFFECTIVE_EVIDENCE 说明固定写成：**不等于 0 分，表示当前记录不足以支持强评价。**

## 方向 A：答辩叙事型（direction-a-defense.svg）

### 设计目标

让评委按“问题 → 模型流程 → 当前案例 → 结论”顺序阅读，适合 10 秒内建立项目心智模型。

### 页面结构

1. 标题区：证据支持的评价框架 + 一句英文副标题。
2. 顶部四卡：观察到的 / 原始表现、证据可靠性、调整后评价、评价状态。
3. 中部横向流程：观察到的表现 → 证据可靠性 → 调整后评价 → 可评价性。
4. 左下案例列表：P105、P072、P033，当前案例高亮。
5. 右下案例解释：Raw / Task level、证据可靠性、调整后评价、正负因素和一句人话解释。

### 为什么适合本项目

它把模型逻辑放在所有细节之前，评委无需猜“分数是怎样被调整的”。四张结果卡与流程图能直接支撑答辩讲解，P105 与 P072 的对照也能把 LOW_SUPPORT 和 NO_EFFECTIVE_EVIDENCE 讲清楚。

### 适用场景

答辩主屏、论文配套演示截图、开场 30 秒讲解。

## 方向 B：分析控制台型（direction-b-console.svg）

### 设计目标

在不变成后台系统的前提下，支持快速切换少量代表案例，并让指标、因子贡献、情景试算 同时可见。

### 页面结构

1. 左侧窄栏：案例列表与状态混合统计。
2. 顶部四张结果卡。
3. 中部模型流程条。
4. 左下案例解释：Raw → 证据可靠性 → 调整后评价。
5. 右下因子贡献：学生证据、Prompt / AI 影响、Context Completeness。
6. 右侧 情景试算 小面板。
7. 底部固定的 NO_EFFECTIVE_EVIDENCE 说明卡。

### 为什么适合本项目

它最适合 Demo 演示：切换 P105、P072、P033 时，评委能看到状态和解释如何联动。情景试算 只展示参数变化、证据可靠性 变化和 调整后评价 稳定性，不引入复杂图表。

### 适用场景

交互演示、现场操作、评委追问“参数变了会怎样”时的补充页面。

## 方向 C：案例讲解型（direction-c-case-lens.svg）

### 设计目标

一次聚焦一个反例，回答“为什么这个案例最终不能被强评价”。

### 页面结构

1. 顶部案例横幅：P072 + NO_EFFECTIVE_EVIDENCE。
2. 四步案例流程：Observed → Evidence → 调整后评价 → 可评价性。
3. 左下证据分解：Student Evidence、Context、Prompt / AI、Confidence。
4. 右下 人话解释：一句人话解释 + NO_EFFECTIVE_EVIDENCE 不等于 0。
5. 底部给出下一步公平解读提示。

### 为什么适合本项目

项目辨识度最高的内容是“缺少有效证据时拒绝伪精确”。此方案把这一点变成页面主角，适合讲真实反例和模型的谨慎边界。

### 适用场景

答辩反例页、评委快速理解、论文中的案例截图。

## 主推荐：方向 A

推荐 A 作为主 Demo 首页，B 作为交互态补充，C 作为反例讲解页。

理由：

- **更利于讲赛题**：首屏先解释“评价不仅看表现，也看证据支持”。
- **更利于讲模型**：四卡 + 四步流程把 Observed → 证据可靠性 → 调整后评价 → 可评价性 直接串起来。
- **更利于讲案例**：案例列表和详情同屏，P105 与 P072 可快速对照。
- **更利于评委短时间理解**：页面主线单一，图表少，状态颜色语义稳定。

## 轻量实现建议

### 必须先做

1. 顶部四张核心结果卡。
2. 横向模型流程条。
3. 案例选择区和当前案例高亮。
4. 详情区的正负因素 + 一句人话解释。
5. 独立的 NO_EFFECTIVE_EVIDENCE 说明卡。

### 锦上添花

- 轻量 情景试算 面板。
- 因子贡献条。
- 状态分布小计数。
- 案例之间的键盘/按钮切换。
- 答辩模式下的“聚焦案例”视图。

### 如果只做 20% UI 改动，优先改这 5 个地方

1. 把原有页面标题改为 证据支持的评价框架，副标题补上“不只评价表现，也评价证据支持度。”
2. 将 Raw、证据可靠性、调整后评价、Status 提升到首屏四卡。
3. 在四卡下增加固定流程条：观察到的表现 → 证据可靠性 → 调整后评价 → 可评价性。
4. 把 Explain 区改成“案例 ID + 正负因素 + 一句人话解释”，示例使用 P105。
5. 新增醒目的 NO_EFFECTIVE_EVIDENCE 说明卡，明确“不是 0 分，而是证据不足以支持强评价”。

## 当前不建议做的 UI 功能

- 大量动画和滚动叙事。
- 复杂后台、多页面 SaaS、登录和权限。
- 金融交易风格大屏。
- 炫技图表、3D 图、SHAP/LIME 式复杂可视化。
- 与模型结论无关的用户管理、数据库、排名、通知系统。
- 把 AI_PROVISIONAL 结果做成“正式评分”或“学生能力排名”。
